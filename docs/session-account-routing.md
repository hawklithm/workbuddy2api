# 会话账号分配与可用性路由

模型可分别开启会话自动分配与异常自动切换，均默认关闭。自动分配需要客户端提供稳定的 session ID；不使用基于消息内容推导的标识作为持久绑定。一个共享 API 凭据下的 session ID 必须由客户端保证唯一，不能将其视为安全隔离凭据。

DeepSeek Harness 的 OpenAI 兼容 `llm-pi-ai` 路由不一定发送 session ID。本项目的 `integrations/deepseek-harness/workbuddy-session-header.mjs` 可注册 `llm-pi-ai/request-headers` 监听器，仅为 `workbuddy` 路由到 `localhost:8787/v1` 或等价 loopback 地址时发送 `x-deepseek-harness-session-id`。可将文件复制到 web profile，并在 `cordis.patch.yml` 中通过 `- insert:` 配置该本地插件；更换路由名、地址或 profile 时必须相应调整并验证。现有显式会话头优先，插件不会将 session ID 发送到其他路由或远程地址。

第一层按 session 和模型持久绑定账号，首次从已证实提供模型的账号中按绑定数量分配；第二层维护账号与模型的可用性。额度受限立即进入冷却，连续五次上游异常仅在异常切换开启时进入短暂冷却。下次请求在事务中检查原绑定并按需更新；已开始的请求绝不重放。冷却恢复后已切换会话不自动切回。模型目录不完整且无法确认当前绑定时保留绑定但拒绝本次请求；所有候选不可用时返回明确错误。

每个模型可排除部分已关联账号，未设置的账号默认允许参与，包括之后新关联的账号；只有同时确认提供该模型的账号才可实际分配。排除生效后，已绑定会话在下一次请求时重新选择；排除表与绑定选择在同一 SQLite 事务边界内检查，即使模型目录部分失败也不会恢复已排除的绑定。排除全部候选时返回无可用账号，不会回退到已排除账号。

状态保存在账号目录内的 SQLite 数据库，通过事务串行化多进程分配与可用性更新；仅保存哈希会话标识，不存放请求内容或凭据。30 天不活跃的绑定会在下次分配时清理，之后的请求可能重新分配。额度限制先冷却一小时，连续异常冷却一分钟；冷却结束只意味着可以再次尝试，不代表已确认恢复。开关关闭后保留绑定，重新启用时可沿用；手动更改路由会重置该模型绑定，但不抹除有独立证据的账号冷却。状态恢复与目录缓存均不能保证上游实际仍有额度，上游拒绝仍应正常返回并记录。
