# 会话账号分配与可用性路由

模型可分别开启会话自动分配与异常自动切换，均默认关闭。自动分配需要客户端提供稳定的 session ID；不使用基于消息内容推导的标识作为持久绑定。一个共享 API 凭据下的 session ID 必须由客户端保证唯一，不能将其视为安全隔离凭据。

第一层按 session 和模型持久绑定账号，首次从已证实提供模型的账号中按绑定数量分配；第二层维护账号与模型的可用性。额度受限立即进入冷却，连续五次上游异常仅在异常切换开启时进入短暂冷却。下次请求在事务中检查原绑定并按需更新；已开始的请求绝不重放。冷却恢复后已切换会话不自动切回。无可靠目录时保留原绑定；所有候选不可用时返回明确错误。

状态保存在账号目录内的 SQLite 数据库，通过事务串行化多进程分配与可用性更新；仅保存哈希会话标识，不存放请求内容或凭据。30 天不活跃的绑定会在下次分配时清理，之后的请求可能重新分配。额度限制先冷却一小时，连续异常冷却一分钟；冷却结束只意味着可以再次尝试，不代表已确认恢复。开关关闭后保留绑定，重新启用时可沿用；手动更改路由会重置该模型绑定，但不抹除有独立证据的账号冷却。状态恢复与目录缓存均不能保证上游实际仍有额度，上游拒绝仍应正常返回并记录。
